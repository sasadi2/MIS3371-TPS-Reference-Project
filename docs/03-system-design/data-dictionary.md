# Data Dictionary

The data dictionary defines the transaction's data contract.

A good dictionary explains not only a field's technical type, but also its **business meaning**.

## Core Transaction Fields

| Field | Business Meaning | Category | Type | Required? | Source | Rule / Constraint | Example |
|---|---|---|---|---|---|---|---|
| transactionId | Stable unique identifier for one official reimbursement request | System | string | System | Application | Unique; generated on official submission | `EXP-2026-00418` |
| employeeId | Organization identifier of employee requesting reimbursement | User | string | Yes | Employee | Must not be empty | `E10427` |
| employeeName | Display name of requesting employee | Derived / reference | string | Later | Directory/application | Should correspond to employeeId | `Jordan Lee` |
| department | Employee's organizational department | Derived / reference | string | Later | Directory/application | Controlled organizational value | `Marketing` |
| expenseDate | Date on which the expense occurred | User | date | Yes | Employee | Valid date | `2026-09-12` |
| expenseCategory | Business category of the expense | User | enum/string | Yes | Employee | Must be one allowed category | `Client Meal` |
| expenseAmount | Dollar amount requested for reimbursement | User | decimal | Yes | Employee | Must be > 0 | `184.50` |
| description | Business purpose / explanation of the expense | User | string | Yes | Employee | Meaningful text required | `Client dinner after project meeting` |
| receiptAttached | Indicates whether receipt evidence accompanies the request | User | boolean | Conditional | Employee | Required when amount > $75 | `true` |
| receiptRequired | Indicates whether policy requires receipt evidence | Derived | boolean | System | Application | `expenseAmount > 75` | `true` |
| directorApprovalRequired | Indicates whether elevated approval is required | Derived | boolean | System | Application | `expenseAmount > 5000` | `false` |
| managerId | Identifier of manager responsible for first-level review | Derived / reference | string | Later | Directory/application | Must map to employee | `M2208` |
| status | Official current transaction state | System | enum/string | System | Application | Must follow allowed state transitions | `UnderReview` |
| submittedAt | Trusted time the request became an official submission | System / audit | datetime | System | Application | Generated by trusted application/service | `2026-09-14T14:22:18-05:00` |
| reviewedAt | Trusted time the manager review decision occurred | System / audit | datetime | Conditional | Application | Created on manager decision | `2026-09-15T10:04:11-05:00` |
| directorReviewedAt | Trusted time director decision occurred | System / audit | datetime | Conditional | Application | Only for director-routed requests | `null` |
| completedAt | Trusted time reimbursement processing completed | System / audit | datetime | Conditional | Application | Created on completion | `2026-09-18T16:40:03-05:00` |
| rejectionReason | Explanation when request is rejected | Reviewer | string | Conditional | Reviewer | Required if decision is reject | `Expense is not reimbursable under policy.` |

## Field Categories

### User-provided data

Entered directly by a human:

- `employeeId`
- `expenseDate`
- `expenseCategory`
- `expenseAmount`
- `description`
- `receiptAttached`

### Derived data

Calculated or looked up from trusted information:

- `employeeName`
- `department`
- `receiptRequired`
- `directorApprovalRequired`
- `managerId`

### System / control data

Used to control and identify the transaction:

- `transactionId`
- `status`

### Audit data

Used to reconstruct important events:

- `submittedAt`
- `reviewedAt`
- `directorReviewedAt`
- `completedAt`

## Week 4 Form Mapping

Not every data-dictionary field belongs in the browser form.

### Fields the employee can enter in Week 4

- employeeId
- expenseDate
- expenseCategory
- expenseAmount
- description
- receiptAttached

### Fields the application will create or control later

- transactionId
- receiptRequired
- directorApprovalRequired
- status
- trusted timestamps

This separation is important. A user should not be allowed to type:

```text
status = Approved
```

and have the system trust that value as the official state.
